## Findings

### [BLOCKING:design] e2e test cannot reach the handoffs it exists for
**Location:** batch 13 card 67 vs batch 12 cards 58/61 **Issue:** card 67 creates `internal/ladder/e2e_test.go` with a library-only `Context:`, but the two most drift-prone handoffs — ingest's `GateReport` → `IngestRecord` assembly (card 58) and record-score's ingest-record → `run.json` observation copy (card 61, "the only path by which an observation taken in the run session reaches the marker the summariser reads") — live in `package main` under `cmd/ladderbench/`, unreachable from that package. **Fix:** decide explicitly whether those two assemblers move into `internal/ladder` (exported, cmd becomes a thin caller) or the e2e test moves to the cmd package; as written the test re-implements the handoff and cannot catch drift in it.

### [BLOCKING:scope] Card 53 Context omits runstate.go
**Location:** batch 11 card 53 **Issue:** the cold-abort path requires "creating that repetition's run directory" and "calling the same invalidation the run session uses ... renames the directory to its `<n>.invalid-<k>` sibling and returns the next attempt index, or errors at the ceiling" — i.e. `RunDirPath`, `Invalidate`, and `MaxAttempts`, all in `internal/ladder/runstate.go`, which appears in neither `Context:` nor `Edits:`. **Fix:** add `bench/loomyard-eval/ladder/internal/ladder/runstate.go` to card 53's `Context:` and name the three identifiers.

### [NIT:decision] cold_abort.json has one writer and an unspecified reader
**Demoted-from:** BLOCKING
**Location:** batch 11 card 53 (writer) vs batch 12 card 63 (reader) **Issue:** card 53 fixes the filename `cold_abort.json` and says it "names the live-daemon cause", but specifies no key names; card 63 must read "the cold-abort record the cold preparation path leaves inside the invalidated sibling directories" without naming the file, without preparesession.go in `Context:`, and without any stated schema. **Fix:** fix the filename and its key set in one place (a batch-local decision or card 53's `Requirements:`), and cite that literal in card 63.

### [NIT:consistency] Card 16 contradicts itself on the blinding gate's outcomes
**Location:** batch 3 card 16 **Issue:** "keeping exactly three checks, each fatal" is immediately followed by the fourth, non-fatal `target_origin_quarry_mention` outcome, and the test list asks for "all four outcomes"; the Python's short-circuit (return before the bare-mention check once any earlier check is fatal, gates.py:232) is also unstated, so the port may emit findings the Python would not. **Fix:** reword to "three fatal checks plus one non-fatal observation" and state the short-circuit.

### [NIT:scope] RunGates' new signature is never given
**Location:** batch 5 card 26 **Issue:** every other non-trivial port states its Go signature, but `RunGates` — whose parameter list changes materially (drops the unused `a_run_dir`, gains `maxTurns` and the pre-computed dirtied observation) — is described only in prose; card 58 is its sole caller and is in a later batch. **Fix:** state the full `RunGates(...)` signature in card 26.

### [NIT:scope] ingest's description derivation is unstated
**Location:** batch 12 card 58 **Issue:** card 58 says ingest "locates the transcript by description" but never says where the attempt index in that description comes from; card 54 pins that rule for `next-run` only. **Fix:** name `NextAttempt` (or the flag) as ingest's source, so the two commands provably build the same string.

### [NIT:scope] Card 49 Context omits server.go
**Location:** batch 10 card 49 **Issue:** "the allowlist probe's session declares the server" requires `MCPConfigDocument` from `internal/ladder/server.go`, which card 48 lists in `Context:` but card 49 does not. **Fix:** add server.go to card 49's `Context:`.
