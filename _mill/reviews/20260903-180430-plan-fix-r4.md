# Plan fix — round 4

Source review: `20260903-175740-plan-review-r4.md` (holistic, REQUEST_CHANGES, 3 BLOCKING / 5 NIT).

## Fixed

- r4 `[BLOCKING:design] BlindingInput omits the server name check (d) requires` — `BlindingInput`
  now carries `ServerName` as its own field, with the reason stated (card 17's redaction input
  carries name and prefix separately, and the two consumers must agree on the giveaway token, so
  re-deriving it in one of them is how they stop agreeing). Card 19 gained a check (d) case for a
  prompt containing the bare server name, run with a server name that is not the word quarry so the
  case fails if the implementation re-derives it from the prefix or falls back to the default.
- r4 `[BLOCKING:scope] Card 35 hand-authors provenance.json without provenance.go` — added
  `internal/ladder/provenance.go` to card 35's `Context:`.
- r4 `[BLOCKING:scope] Card 28 computes gate 1 without config.go in Context` — added
  `internal/ladder/config.go` to card 28's `Context:`, and the card now states that gate 1 is called
  with a `Config` synthesised from the run-state fields, naming which four fields that is and why
  synthesising it is what lets the summariser call the same gate without loading the ladder file.
- r4 `[NIT:consistency] provenance.json can carry absolute host paths` — the finding is correct and
  the record leaked host paths through two fields. `ladder_file` is now stored repository-relative
  when the operator's value resolves under the repository root, and as its base name otherwise. The
  resolved auto-memory directories are no longer stored in the record at all: it carries
  `memory_path_hashes` (the sha256 of each), while the paths themselves go to `raw/memory-paths.json`
  inside the untracked raw tree, which the resumed-run scan reads. That is a **deliberate refinement
  of the discussion's own wording**, which said the paths live in the provenance record while also
  fixing that record as committed and forbidding machine paths in tracked files — two statements
  that cannot both hold; the refinement, its reasoning and the reason resume is unaffected (a root is
  only ever resumed on the host that produced it) are written into card 23. Card 26 was updated on
  both the write and the resume side, including the disposition for a record whose hashes are present
  but whose paths file is missing. Card 24's round-trip assertion now scans the marshalled bytes for
  the temporary directory's own prefix, so it fails if any future field reintroduces a path.
- r4 `[NIT:decision] Six Provenance fields have no producer` — `Invocation` now carries
  `ladder_file`, `quarry_dirty_files`, `loomyard_commit`, `loomyard_repo_sha256` and `server_name`
  alongside its existing fields, so every merged top-level field has a carrier; `CollectInvocation`
  is stated to fill all of them and its two deliberate exceptions are named (the server-hash map and
  the memory-path hashes, both learned later by the run loop). Session fingerprints are stated to be
  written into the record by the run loop as each repetition completes, with the reason a
  once-per-invocation collector cannot produce them. The merge rules now give every top-level field a
  derivation: union, merge-by-key, latest-wins, or must-be-identical, the last extended to the ladder
  file, the target-repository hash and the server name.
- r4 `[NIT:decision] Root-level output filenames never fixed` — `ProvenanceFile`, `SummaryFile` and
  `TableFile` are now package-level constants, each declared in the file that writes it (cards 23,
  28 and 29), matching how card 25 pins the six per-repetition names.
- r4 `[NIT:consistency] A third matching class appears in card 20` — the matcher's doc comment is now
  **scoped** rather than extended: the two classes govern content the harness searches, which is what
  keeps the gates and the redactor from drifting on the giveaway token. Card 2 states explicitly that
  the worktree-root startup assertion is not one of them and does not route through `match.go` — it
  tests a filesystem path rather than content, is deliberately case-insensitive where the
  composed-string form is case-sensitive, and has one caller. Card 20 records the same boundary from
  the other side. Adding a third exported matcher used once would have made the "one place" rule
  weaker, not stronger.
- r4 `[NIT:decision] ScanMemoryPaths has no stated missing-directory behaviour` — card 23 now divides
  the two return channels explicitly: a named path that does not exist is a **fatal `*Finding`**
  (the harness cannot tell "clean" from "never scanned", which is the exact silent failure the
  read-not-derive decision exists to prevent); an empty path list is neither finding nor error and
  the run continues, since an absent memory directory is the outcome the check wants; the `error`
  channel is reserved for I/O failures on things that do exist. Card 24's cases were updated to
  match, including the new empty-list case.
