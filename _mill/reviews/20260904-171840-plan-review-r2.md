## Findings

### [BLOCKING:design] Batch 4 verify can go red inside batch 1's TDD window
**Location:** 00-overview.md batch index, batches 1 and 4
**Issue:** Batch 4 declares `depends-on: [2, 3]` and `verify: go test ./bench/loomyard-eval/ladder/internal/ladder/` (whole package), while batch 1 declares `depends-on: []` and deliberately lands failing `e2e_test.go` assertions in card 4 that stay red until card 5 — the two batches are unordered, so batch 4's own verify can fail on batch 1's uncommitted-yet-in-progress state rather than on its own diff.
**Fix:** Make batch 4 `depends-on: [1, 2, 3]` (batch 5 already depends on both, so the added edge costs no extra serialisation), or narrow batch 4's verify to a `-run` filter excluding `TestE2E`.

### [NIT:scope] Card 2 does not assert the rune-safe truncation card 1 mandates
**Location:** 01-m2-invalidation-reason-file.md, cards 1–2
**Issue:** Card 1 requires `sanitizeDetail` to truncate "without splitting a UTF-8 rune", but card 2's over-length case asserts only `len(...) <= invalidReasonDetailMaxLen` and a trailing ASCII `...` — both of which a naive byte slice that splits a rune also satisfies, so the one non-obvious requirement in card 1 ships unverified.
**Fix:** Add a multi-byte-rune detail case asserting `utf8.ValidString` on the rendered `detail` value.

### [NIT:consistency] Batch 4 scope says "every control cell"; card 13 covers three of four
**Location:** 04-ladder-file-and-pre-matrix-gates.md, Batch Scope vs card 13
**Issue:** The Batch Scope promises `CheckRenderedControlPrompt` returning nil "for every control cell's fully rendered prompt", but `TestPreMatrix_ControlPromptsAreBlind` enumerates only `b0-none`, `c0-none`, `d0-none`; `a0-none` is a control in the same amended file and is left unguarded.
**Fix:** Either add `a0-none` to the card's id list or reword the Batch Scope to "every control cell this matrix runs".

### [NIT:scope] Card 6 names `ExplorationRule` without score.go in Context
**Location:** 02-ladder-c-task-02.md, card 6
**Issue:** Card 6's `Requirements:` cites `ExplorationRule` as the reason both schema blocks must stay identical, but `score.go` (where that constant lives) is in card 7's `Context:` and not card 6's.
**Fix:** Add `bench/loomyard-eval/ladder/internal/ladder/score.go` to card 6's `Context:`, or drop the identifier from the rationale.

### [NIT:decision] Card 7's subject-swap remedy leaves the task id undisposed
**Location:** 02-ladder-c-task-02.md card 7 (and 04's card 10)
**Issue:** If ladder c's subject is swapped, card 7 says only to re-author and record the swap in the notes — it does not state whether the file name `02-shedadapters-exploration.md`, the fasit `_meta.task` value, and card 10's hardcoded `tasks:`/`configs:` keys keep the now-misleading `shedadapters` id; card 12's `droppedSubstrings` guidance (`8.4k lines`) would also be stale. Card 9's equivalent remedy has no such exposure because task 06's name is subject-neutral.
**Fix:** State explicitly that a swap keeps the `02-shedadapters-exploration` id, file name and ladder entry, and changes only the prompt body, scope section and notes.
