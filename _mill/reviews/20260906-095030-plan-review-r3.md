## Findings

### [NIT:consistency] Decision says absolute root, card 29 writes relative
**Demoted-from:** BLOCKING
**Location:** `00-overview.md` `### Decision: results-root-date-resolved-once` vs batch 1 card 29, preflight step 3
**Issue:** The Shared Decision states card 29 "writes the resolved **absolute** results-root path" into `.scratch/kickstart-results-root.txt`; card 29's own Requirements prescribes `RESULTS_ROOT=` followed by "the **worktree-relative** results-root path". Cards 30-32 consume that file, so the two spellings are not interchangeable for a reader deciding what to write.
**Fix:** Make one spelling authoritative in both places (relative is the one card 30's `--results <RESULTS_ROOT>` invocation from the worktree root actually needs).

### [NIT:decision] Void primary test has no M4b / roadmap disposition
**Demoted-from:** BLOCKING
**Location:** batch 1 cards 31 and 32 (edit 3)
**Issue:** Card 31 defines a third outcome — realised n below ten in either tested arm makes the primary test **void**, with "no separation conclusion" drawn — but both cards' M4b dispositions branch only on "e1 separates" / "e1 does not separate". Card 32 edit 3 then forces a choice between deleting the M4b conditional (asserting a negative the void run cannot support) and adding M4b (asserting a positive it cannot support either), and edit 1's standing-rule sentence has no wording for it.
**Fix:** State the void branch explicitly for card 31's one-sentence M4b reading and for card 32 edits 1 and 3 (e.g. carry the conditional forward unchanged, citing the void root).

### [NIT:scope] `.scratch/kickstart-run.log` created but not declared
**Location:** batch 1 card 30, launch block
**Issue:** The `nohup ... > .scratch/kickstart-run.log` launch creates a file the card's `Creates:` does not list, while card 29 declares the equally git-ignored `.scratch/kickstart-results-root.txt` under `Creates:`. The convention is applied inconsistently within one batch.
**Fix:** Either declare the log under card 30's `Creates:` or state once in the batch scope that git-ignored scratch paths are undeclared.

### [NIT:consistency] resolve exit-code gloss is not the pack's own gate
**Location:** batch 1 card 29, "Contingency branch — enumerate the failures first"
**Issue:** The card treats exit 1 from `go run ./cmd/quarry resolve` as the failure signal, but `codeForResolveResult` (`internal/cli/cli.go:85-96`) returns exit 0 for `StatusMultipart` as well as `StatusFound`, whereas `RenderKickstartPack` (`bench/loomyard-eval/ladder/internal/ladder/pack.go:47-64`) is fatal on any status other than `StatusFound` and on a found result carrying other than exactly one symbol. The enumeration can therefore count zero failures for a pack that failed, and the halt test ("exactly one" / "two or more") has no zero branch.
**Fix:** Key the enumeration on the `--text` output's status word being `found` with one symbol, and add a zero-failure branch that halts.

### [NIT:consistency] Batch Tests under-enumerates what `-run 'TestPreMatrix'` runs
**Location:** batch 1 `## Batch Tests`
**Issue:** The section names five `TestPreMatrix_*` functions, but the regex also selects `TestPreMatrix_ControlPromptsAreBlind` (`prematrix_test.go:41`), which is keyed on `ladder-toc.yaml` rather than on this batch's artefacts.
**Fix:** Name the sixth test, or say the `-run` selector is broader than the four kick-start checks the batch relies on.
