## Fixed

- r5 `[BLOCKING:design]` "Server-connect invalidation is unbounded across reps" — accurate and the
  most valuable finding of the round: `MaxAttempts` bounds retries per repetition, so a five-
  repetition cell hitting a systematic connect failure would spend up to 15 measured `claude -p`
  calls against a whole-task budget of 10, and only report after the invocation returned. Card 5 now
  uses the `abortRun` disposition `run.go` already carries for a tainted memory-path scan: when a
  repetition exhausts its attempts *and every attempt failed this check*, the whole invocation
  stops. Three consecutive failures to connect the same server is a configuration fault, not bad
  luck. That caps the blast radius at 3 calls rather than 15 and surfaces it while the operator can
  still act. Ordinary within-repetition retries are explicitly preserved — one failed attempt
  followed by a success is transient and aborts nothing.
- r5 `[BLOCKING:design]` "No disposition for a transcript with no session-init record" — accurate;
  `run.go` nil-guards `transcript.Init` at both existing uses and the attempt loop's accept branch
  tests only the result record, so nil reaches the new call site and the natural implementation
  dereferences it. Card 5 now states the disposition — nil is a **finding, not a pass**, because for
  a granted cell a transcript with no init record cannot show the server ever loaded, and treating
  absence of evidence as a pass is the reasoning this batch exists to undo — requires the guard
  first, requires the message to read distinctly from the server-absent case, and adds the nil case
  to the `gates_test.go` list.
- r5 `[NIT:scope]` "New fingerprint status map and diff clause get no test" — accurate:
  `TestCompareFingerprints` builds fingerprints from named-field literals and would stay green while
  exercising neither addition. Card 3 gains `provenance_test.go` in its `Edits:` and two required
  cases — `NewSessionFingerprint` populating the map from a retyped record, and
  `diffSessionFingerprint` reporting a status-only difference between two otherwise identical
  fingerprints. Without the second, a server that silently stopped connecting mid-cell reads as no
  drift at all, which is precisely what the field was added to catch.
- r5 `[NIT:consistency]` "New fixture sits outside the package's testdata layout" — the fixture moves
  to `testdata/transcripts/`, matching every other transcript fixture and the shared
  `parseTranscriptFixture` helper's hardcoded prefix, in both card 4 and All Files Touched.
- r5 `[NIT:consistency]` "`the-code-under-test-is-not-edited` forbids what batch 2 does" — accurate
  and worth fixing precisely because the implementer reads the card, not the rationale. The decision
  now says *repository-root* `internal/`, `quarry/`, `cmd/`, and names the harness tree's own
  `internal/` and `cmd/` directories as the legitimate exception batch 2 and card 7 rely on.
