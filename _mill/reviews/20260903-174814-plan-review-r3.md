## Findings

### [BLOCKING:design] Golden files cannot match a nondeterministic header
**Location:** batch 8 card 35 vs batch 7 cards 28, 29
**Issue:** Card 35 compares the produced summary and table "byte-for-byte" against committed goldens, but card 28 puts the results root **and the write time** in `Summary`'s meta block and card 29 puts the results root in the table header — and card 35 runs over a copy of the fixture in `t.TempDir()`, so both values differ on every run.
**Fix:** State in card 35 which fields are normalised or excluded before comparison (or make cards 28/29 store a root-relative identifier and no wall-clock time).

### [NIT:consistency] Results root in summary.json/table.txt contradicts a Shared Decision
**Demoted-from:** BLOCKING
**Location:** `## Shared Decisions` → no-machine-paths-in-tracked-output vs cards 28, 29
**Issue:** The decision says "`summary.json` and `table.txt` carry cell ids and metrics only", yet both cards require the results root in their output; those two files land at the results root, which is tracked (only `results/*/raw/` is ignored per the gitignore-scope decision), so an absolute `--results` value becomes a machine path in a tracked file.
**Fix:** Give the disposition explicitly — either the decision permits a repo-relative root, or cards 28/29 drop it.

### [BLOCKING:design] Gate-2 fatal disposition never states the blinding-failed flag is set
**Location:** batch 6 card 26 ("Dispositions") vs card 25, card 28, card 34
**Issue:** Card 26 sets `blinding_failed` only for the pre-dispatch check (d); the gate-2 fatal case is described merely as "complete as a failed repetition". But `RepIsComplete` (card 25) returns false only when that flag is true, card 28 builds the invalid slice from it, and card 34 asserts it is set — if the flag is not written, a gate-2 failure satisfies resume and is silently never re-attempted.
**Fix:** Card 26 must state that a fatal gate-2 finding writes the repetition complete with `blinding_failed` true.

### [BLOCKING:scope] Test cards name identifiers from files absent from `Context:`
**Location:** batch 3 card 15; batch 4 card 19
**Issue:** Card 15's `Requirements:` invokes "the shared bare-token matcher" (`match.go`) and "the four built-in tools" (`BuiltinTools`, declared in `config.go` by card 3) while listing neither file in `Context:`/`Edits:`; card 19 likewise names the four built-in tools without `config.go`. The overview's the-four-built-in-tools decision explicitly forbids re-spelling the names, so the implementer must read `config.go`.
**Fix:** Add `config.go` to both cards' `Context:` and `match.go` to card 15's.

### [NIT:consistency] CLI flag spellings exist only in a card the CLI card cannot read
**Demoted-from:** BLOCKING
**Location:** batch 1 card 5 vs batch 7 card 30
**Issue:** Card 5 writes `--config`, `--results`, `--cells` and `--reps` literally into the migrated `ladder-toc.yaml` header (and into the T2/T7 run instructions), but card 30 describes the flags only by role and does not list `ladder-toc.yaml` in its `Context:`, so batch 7 can legitimately implement `--ladder`/`--out` and contradict the documented entry point the hand-run done-criterion uses.
**Fix:** Name the four flag spellings in card 30's `Requirements:` (the overview already fixes `--claude-bin`).

### [BLOCKING:scope] Summariser never names the score-record keys it reads
**Location:** batch 7 card 28 (also card 31, card 29)
**Issue:** Card 28 says it "reads that repetition's recall and precision from its score record", but card 17 derives each schema's required field set from that rule's own fenced example, and the ladder file carries both an exploration and an impact group; the two rules may not spell those two keys identically, and nothing says what a cell whose rule lacks them reports.
**Fix:** Name the exact score-record keys per schema (or state the mapping the summariser applies).

### [NIT:consistency] Batch 4 scope names the wrong consumer of gate 1
**Location:** batch 4 `## Batch Scope`
**Issue:** It states "the external interface batch 6 consumes is `CheckGrantedToolUsed`, ...", but no card in batch 6 calls it; gate 1 is computed by card 28 in batch 7.
**Fix:** Attribute `CheckGrantedToolUsed` to batch 7 in that sentence.

### [NIT:scope] `ladder.env` location is spelled two different ways
**Location:** batch 5 card 20 vs card 22
**Issue:** Card 20 says the env file sits in "the scratch directory directly under the quarry repository root" without naming it, while card 22 spells `.scratch/ladder/`; the tracked artefact is `.scratch/ladder.env` and the root `.gitignore` ignores `.scratch/`.
**Fix:** Spell `.scratch/ladder.env` literally in card 20.

### [NIT:consistency] Scorer retry ceiling and the fasit meta key are spelled as prose
**Location:** batch 6 card 26; batch 4 cards 17, 19
**Issue:** Card 26 says the scorer retries "up to three attempts" without saying whether that is card 25's `MaxAttempts` constant; cards 17/19 say "top-level meta block"/"meta key" while the committed fasit's key is `_meta`.
**Fix:** Reference `MaxAttempts` explicitly and name the literal `_meta` key.
