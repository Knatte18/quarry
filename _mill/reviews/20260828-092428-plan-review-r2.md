## Findings

### [NIT:consistency] Batch 4 verify differs between index and batch file
**Demoted-from:** BLOCKING
**Location:** `00-overview.md` Batch Index (batch 4) vs `04-docs-and-live-tier.md` frontmatter
**Issue:** The index says `go build ./... && go vet -tags lsp ./internal/cli/ && go test ./internal/quarryengine/ ./internal/cli/...`, the batch file says `go build ./... && go test ./internal/quarryengine/ && go test -tags lsp ./internal/cli/`; the index (the authoritative DAG) only *vets* the `lsp` tier, so card 17's live-tier test is never run by any gate — `pipeline.done_gate` in `mill-config.yaml` is confirmed untagged `go test ./...`.
**Fix:** Make the index entry byte-identical to the batch file's `verify:`, so the tagged tier actually runs.

### [BLOCKING:scope] Doc-site ownership map omits internal/cli/toc.go
**Location:** `00-overview.md` Decision `doc-site-ownership-by-touching-batch`; batch 4 card 16 sweep
**Issue:** `internal/cli/toc.go:7` hand-enumerates the LSP-backed verb set — "Those helpers ... exist for the language-server-backed verbs (refs/definition/symbol/assert-no-callers)" — and goes stale the moment `impact` (which uses `resolveContext`/`buildOptions`) lands; the decision names no owner for that file, it is absent from `## All Files Touched`, and card 16's sweep is explicitly scoped to "every site the decision names".
**Fix:** Assign `internal/cli/toc.go` to batch 3 (which already owns the CLI-package doc sites) and add it to `## All Files Touched`.

### [NIT:design] Card 11's --help-ordering rationale is false
**Location:** Batch 3, card 11
**Issue:** "placed after the `assert-no-callers` registration and before the `toc` group, so the verb ordering in `--help` matches the README's list" — cobra's `EnableCommandSorting` defaults to true and is never disabled in this repo (no occurrence anywhere), so `--help` lists subcommands alphabetically regardless of `AddCommand` order.
**Fix:** Keep the placement but restate the reason as source-order readability, not `--help` output.

### [NIT:consistency] --timeout help string copied from the wrong verb
**Location:** Batch 3, card 10
**Issue:** The card says register `--timeout` "matching `refsCommand`'s set and its help strings", i.e. "deadline for each LSP request phase (initialize, resolve, references)", but `impact` goes through `query.Callers`, which also runs definition, implementation, and per-reference verification phases; `assertNoCallersCommand` already uses the wider "(initialize, resolve, references/definition)" wording.
**Fix:** Name `assert-no-callers`' phase enumeration as the one to copy for `--timeout`.

### [NIT:design] Cancellation scope undefined for the definition-side parse
**Location:** Batch 1, cards 5 and 7
**Issue:** Card 5 scopes the `ctx.Err()` check to "immediately before resolving a reference whose file is not already cached", which excludes the `declaration[0]` enclosing lookup, while card 7's test says "a context already cancelled before the first cache-miss parse" — which, with a non-empty declaration set, is the definition-side parse.
**Fix:** State in card 5 whether the definition-side lookup is also cancellation-checked, and align card 7's case wording to that answer.

### [NIT:scope] Card 5 names toc.TOCFile without toc/toc.go in Context
