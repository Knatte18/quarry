## Fixed

- r3 `[BLOCKING:design]` "No recovery when the terminal invocation returns an error" — verified
  against `main.go`'s `runCommand`, which returns on `ladder.Run`'s error before
  `summarizeAndReport` is ever reached, leaving `summary.json` and `table.txt` absent or stale while
  `provenance.json` stays current. Card 4 now carries an explicit disposition: whenever the final
  invocation ends on an error, run the `report` subcommand against the results root before the
  commit, which re-derives both artifacts from the raw tree and the existing provenance record
  without running or scoring anything, and log that it was done and why.
- r3 `[NIT:decision]` "`.ladder.lock` has no disposition between invocations" — verified against
  `AcquireRunLock`, which refuses outright on an existing file. Card 4's before-each-re-invocation
  checklist now leads with the lock check, and states that a lock-refused invocation measured
  nothing and does not consume an arm of the three-invocation ceiling, since that ceiling bounds API
  spend and this failure spends none.
- r3 `[NIT:consistency]` "Card 8 leaves HANDOFF §1's merged-wave inventory stale" — card 8 gains a
  fifth edit, step (0a), covering §1's "Waves 0–3 are merged" inventory and its "Uncommitted on
  `main` right now" snapshot; the former steps (0) and (2) are renumbered and the closing
  restriction now reads "no section other than the five named above".
- r3 `[NIT:decision]` "The clean-tree obligation names no owning card" — the
  `clean-tree-and-no-edits-mid-matrix` decision now names who discharges it: the pipeline's own
  per-card and per-phase commits, not the two zero-diff gate cards, which are gates confirming that
  happened. The remedy on failure is stated too — stop and name the file, which belongs to whichever
  card should have committed it — because a gate card must not sweep another card's diff into an
  unrelated commit.

`SessionInit.MCPServers` is typed `[]string` at `stream.go:113`, but Claude Code 2.1.236 emits
objects in the session-init record, so transcript parsing fails on line 1 for every cell that
actually loads an MCP server. Control cells pass only because their empty list unmarshals into
either shape, which is why the harness has never completed a rung cell. Fixing it requires a new
batch — retype plus a regression test built on a verbatim real init line, and a decision on whether
a non-`connected` server status should invalidate the repetition — inserted before the matrix batch.
That restructure is deliberately **not** in this fix pass: it needs two operator inputs (the source
of the verbatim fixture line, and confirmation of the invalidate-rather-than-fatal call), and
folding a brand-new, never-reviewed Go batch in at the round cap would ship it unreviewed. It is the
first work of the resumed review pass.
