## Pushed Back

- r1 `[NIT:decision]` "The done gate exists only in prose", **suggested fix only** ("Put the decided
  command in the overview's `verify:` field"). The finding's premise — that the gate is untraceable
  — was accurate and is fixed: the Shared Decision, and all three Batch Tests sections, now name
  `pipeline.done_gate` in the hub's `mill-config.yaml`, which already holds exactly
  `go test ./... && golangci-lint run`, as the gate's machine-readable home, and mill-plan's own
  Done-gate section documents that mill-go runs that key from `git_root` before marking the task
  done. The specific remedy is declined under harm category (c). The overview's `verify:` field is
  documented in `plan-overview.md` as "a module-wide check run at each batch boundary AFTER the
  batch's own `verify:` passes" — putting the done gate there would run a full `go test ./...` plus
  a lint pass three times, once per batch boundary, two of those after batches that change no Go
  code at all, to produce a signal `pipeline.done_gate` already produces once. That is duplicated
  cost, not a second gate, and it would also make a plan-level field disagree with the config key
  that actually governs the transition to done.
