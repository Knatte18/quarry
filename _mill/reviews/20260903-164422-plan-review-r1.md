## Findings

### [BLOCKING:scope] Completeness test cannot see card 5's reject rows
**Location:** batch 2, card 6 (with card 5)
**Issue:** Card 6's completeness test must range over "reject rows in both files", and `ReasonUnsupportedLanguage` is produced only in `parse_test.go`, but card 5 specifies no package-level table for those cases and card 6 has `Edits: none`, so it may not add one.
**Fix:** Have card 5 declare a named package-level reject slice (e.g. `parseReject`) that card 6's completeness test ranges over alongside `goReject`, or list `glyph/parse_test.go` under card 6's `Edits:`.

### [NIT:consistency] Card 5's import ceiling excludes reflect but requires Glyph comparison
**Demoted-from:** BLOCKING
**Location:** batch 2, card 5
**Issue:** Card 5 caps imports at `testing` and `errors`, yet every reject assertion must check "the returned `Glyph` equals `Glyph{}`"; `Glyph` holds two `[]string` fields so `==` does not compile, and the Shared Decision mandates `reflect.DeepEqual`.
**Fix:** Add `reflect` to card 5's stated import list, matching card 6's.

### [BLOCKING:scope] Card 8 must read three files absent from its Context
**Location:** batch 2, card 8
**Issue:** Requirement 4 is "read the import lines of the three `_test.go` files", but `Context:` lists only `docs/glyph.md` and `go.mod`, so the files the card's central check operates on are not readable under the Context rule.
**Fix:** Add `glyph/parse_test.go`, `glyph/golang_test.go` and `glyph/string_test.go` to card 8's `Context:`.

### [BLOCKING:design] Card 1 forward-references Language, leaving a non-compiling commit
**Location:** batch 1, cards 1–2
**Issue:** `glyph/errors.go` declares `ParseError.Lang Language` while `Language` lands in card 2, so card 1's commit does not build; the card states this outright rather than avoiding it, and card 2 depends on nothing in `errors.go`.
**Fix:** Swap the two cards — create `glyph/doc.go` + `glyph/glyph.go` first, then `glyph/errors.go` — so each commit compiles.

### [NIT:consistency] Const block drops the Reason type on fifteen of sixteen constants
**Location:** batch 1, card 1, requirement 2
**Issue:** Only `ReasonUnsupportedLanguage Reason = "..."` carries the type; the remaining fifteen are written `ReasonInvalidUTF8 = "invalid_utf8"`, which a literal transcription makes untyped string constants rather than `Reason`, unlike `toc.Kind`'s block where every constant is typed.
**Fix:** State that every constant in the block carries the explicit `Reason` type, as `internal/quarryengine/toc/types.go` does for `Kind`.

### [NIT:consistency] Shared Decision's test-import enumeration disagrees with the cards
**Location:** overview, "standard library only" Decision; cards 5–6
**Issue:** The Decision says the tests "add only `reflect`, `slices`, `strings` and `testing`", but cards 5 and 6 both require `errors`, no card uses `slices`, and card 6's `strings` has no stated use (an unused import fails to compile).
**Fix:** Restate the enumeration as `errors`, `reflect`, `strings`, `testing` and drop `slices`/unused entries from the per-card ceilings.

### [NIT:consistency] Batch 1 scope miscounts its files
**Location:** batch 1, Batch Scope
**Issue:** The scope says the batch is "five files"; it creates four — `doc.go`, `errors.go`, `glyph.go`, `string_test.go`.
**Fix:** Correct the count to four.

Three cross-card wiring gaps and one non-compiling commit order; the spec transcription itself is faithful.
