### [BLOCKING:scope] Card 8 invalidates three existing parser test rows
**Location:** batch 2 / card 8
**Issue:** `TestParseArgs_UsageErrors` in `internal/cli/flags_test.go` holds `{"missing-verb", []string{}, "no verb given; expected: toc"}`, `{"first-arg-is-flag", ..., "no verb given; expected: toc"}` and `{"unknown-verb", []string{"resolve", "t"}, "unknown verb: resolve"}` — the first two assert a message this card changes, and the third uses `resolve`, which this card makes a valid verb (so `parseArgs` returns a nil error and the row hits `t.Fatalf`).

### [NIT:consistency] Card 11 calls runExpand before card 12 declares it
**Demoted-from:** BLOCKING
**Location:** batch 3 / card 11 (vs card 12)
**Issue:** card 11 requires `Run` to "switch on `req.verb` and call `runTOC`, `runResolve` or `runExpand`", but `runExpand` is created by card 12, so card 11's own commit does not compile; card 11 also cannot know card 12's deliberately different arity (`runExpand(req, root, stdout, stderr)` — no `base`).
**Fix:** either move the three-way dispatch into card 12, or have card 11 dispatch `toc`/`resolve` only and state that card 12 adds the `expand` arm and its signature.

### [NIT:decision] The payload-carries-engine-text rule is not in Shared Decisions
**Demoted-from:** BLOCKING
**Location:** overview `## Shared Decisions`; batch 3 / cards 11 and 12
**Issue:** card 11 requires a path escaping the root to emit "the engine's own error string, emitted verbatim" — which is `engine: resolve target "../x": engine: target outside repository` (`internal/engine/repo.go:46,86`) — while card 12 cites "the existing rule forbids leaking the engine's package-name prefix through an exit-1 or exit-2 message" as binding; `internal/cli/cli.go`'s `Run` doc comment states that rule unqualified. discussion.md's D10b resolves this (the rule binds quarry-authored sentences, not `ResolveResult.Error`), but no plan file records it.
**Fix:** lift D10b into `## Shared Decisions` as its own `### Decision:`, so an implementer of card 11 cannot "fix" the prefix and break the golden and end-to-end assertions.

### [BLOCKING:design] Card 11's fixture spec contradicts card 11's own expected result
**Location:** batch 3 / card 11
**Issue:** the card extends the shared fixture with "one free function ... and a second file declaring the same function name under a different build tag", yet its first case expects "a glyph naming the free function: exit 0, a payload whose status is found" — two declarations of that name resolve to `StatusAmbiguous` per `statusForMatches` (`internal/engine/resolve.go:188`); no card-11 case uses the duplicate at all, and card 14 builds its own tree for the ambiguous status.
**Fix:** name the duplicated declaration distinctly from the free function the found case uses, or drop the build-tag second file from card 11's fixture and leave it to card 14.

### [NIT:consistency] Card 6 says five renderers, then lists seven
**Demoted-from:** BLOCKING
**Location:** batch 1 / card 6
**Issue:** the card requires `quarry/doc.go` to state "the package owns five renderers: the two existing JSON ones, the two new JSON ones, and the three text ones" — that enumeration is seven (`RenderJSON`, `RenderErrorJSON`, `RenderResolveJSON`, `RenderExpandJSON`, `RenderText`, `RenderResolveText`, `RenderExpandText`); the adjacent "three JSON success renderers" clause is correct.
**Fix:** change the count to seven, or restate the sentence so the number and the enumeration agree.
