### [BLOCKING:consistency] toc-file.json golden omits the file-target symbols default
**Location:** `internal/mcpserver/testdata/golden/toc-file.json:6-10`
**Issue:** The golden's `alpha.go` file entry carries no `symbols` key, but the "file-default" case
(`internal/mcpserver/toc_golden_test.go:42`) calls `target: "alpha/alpha.go"` with no `depth`/`symbols`
arguments. Per `internal/engine/toc.go:39` ("`opts.Symbols` nil means true for a file target") and per
`internal/mcpserver/toc.go:65` (`wantSymbols := opts.Symbols == nil || *opts.Symbols`), a file target
with symbols omitted must populate `Symbols`. `internal/mcpserver/toc_defaults_test.go:75-95`
(`TestAbsentSymbols_FileDefaultOn_DirDefaultOff`) asserts exactly this for the identical input
(`alpha/alpha.go`, no extras) and would pass, while `toc-dir-symbols-true.json:8-53` shows the same
file's populated symbol array for the same unit (`alpha`), proving the unit is spellable and the array
is non-empty when computed. The committed golden therefore does not match what the shipped code
produces for this input, and `go test ./internal/mcpserver/...` (without `-update`) will fail
`TestGolden_TOC/file-default`.
**Fix:** Regenerate `toc-file.json` with `-update` against the current fixture and code, and review the
diff before committing — per the file's own header instruction that a hand-written or stale golden
"pins the wrong bytes and then passes forever."
