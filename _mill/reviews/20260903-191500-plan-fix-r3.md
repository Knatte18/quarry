## Fixed

- `[BLOCKING:scope]` "Card 30 uses SpansOf a batch before it exists" — verified: the clause was
  introduced by round 2's own fix and `SpansOf` is first declared in batch 5. The assertion is
  removed from card 30, which now says explicitly that the lookup does not exist yet, and re-stated
  in batch 5 card 34 as its own bullet over the same two fixtures — so the walk's "no symbols
  there" and the lookup's "no spans there" stay one statement rather than two.
- `[BLOCKING:design]` "The walk parses every Go file up to three times" — verified against card 17
  as written: `dirPackage`, `dirDoc` and `fileEntry` each opened and parsed the same file. Card 17
  now pins **two** passes and says why two rather than one is forced: the glyph unit batch 4 threads
  into extraction is a directory-level fact, so nothing can be extracted before every clause in the
  directory is read. `dirDoc` no longer parses at all — its signature changes to select among the
  package-doc strings `fileEntry` already produced, and `fileEntry` returns that string alongside
  its entry. The remaining cost is priced with the discussion's own measurement rather than waved
  through.
- `[NIT:consistency]` "HeadStart/HeadEnd defined two different ways" — verified: `Symbol.Start` is
  the doc block's first line, not the declaration's, so cards 23 and 26 disagreed for every
  documented type. Resolved in favour of card 26's reading, which is what the task's own contract
  says: the head span is the symbol's own `Start`/`End` pair, doc block included. Cards 23 and 28
  now say so in the same words, and card 23 states what the expand verb renders from that range.
- `[NIT:decision]` "The Loomyard goldens have no disposition without a checkout" — verified: the
  goldens were unconditional `Creates:` producible only under `-update` against a pinned checkout.
  Card 36 now states the disposition outright: source the gitignored `.scratch/ladder.env` and
  generate them, and if no checkout at the pin is available the card is **blocked** and reported as
  blocked — never satisfied by hand-written goldens, which would pin the wrong bytes and pass
  forever. This machine does have the checkout, at the pin, and `.scratch/ladder.env` now names it.
- `[NIT:scope]` "Card 20's toc_test.go inventory is incomplete" — verified: two cases were
  unaccounted. `TestTOCFile_GoFileWithSymbols` is now named as ported;
  `TestTOCFile_NonexistentPath` is named as deleted, superseded by card 21's `ErrTargetNotFound`
  case rather than ported as a weaker second assertion of the same rule.
- `[NIT:consistency]` "Stale-comment instructions do not match the source" — all three verified and
  each named in the card that invalidates it: `treesitter.go`'s "parsing backend for the toc verbs"
  in batch 1 card 2 (the card's old wording pointed at a package path the header does not carry),
  `extension.go`'s "all views over the single map below" in batch 2 card 11, and `FirstParagraph`'s
  "Both TOCFile and TOCDir call FirstParagraph" in batch 3 card 18, which also gains
  `internal/engine/text.go` in its `Edits:`.
- `[NIT:consistency]` "The root's .gitignore is extended twice in the SpansOf recipe" — verified as
  a literal double-extend. Cards 32 and 38 now start the per-directory chain at the first directory
  **below** the root and say the root is never extended a second time.
- `[NIT:scope]` "Card 17 does not say whether dirPackage sees filtered entries" — verified: nothing
  said so, and a gitignored `.go` file could have voted in the package tie-break. Card 17 now states
  that `dirPackage` and `dirDoc` see the already-filtered entry set, matching what card 32 already
  makes explicit for the lookup side.
