## Pushed Back

- `[NIT:consistency] Per-batch module-wide vet is claimed but not configured` — **factually wrong.**
  The finding says the module-wide vet "appears solely as the task-level `verify:`" and that only batch
  1 runs anything module-wide. The overview-level `verify:` key *is* the per-batch-boundary mechanism,
  not a task-level one: `plugins/mill/templates/plan-overview.md` documents it as "an OPTIONAL
  module-wide check run at each batch boundary AFTER the batch's own `verify:` passes", and
  `millpy-implement.py` implements it — `module_wide_verify_cmd` is parsed from the overview's
  frontmatter and run per batch against a baseline computed once, which `mill-go-base/SKILL.md` calls
  the "per-batch module-wide gate" and whose baseline step it fires "for the task's FIRST batch only".
  Adopting either half of the offered fix would make the plan worse: dropping the "at each batch
  boundary" clause would state something untrue, and copying `go vet ./...` into each batch's own
  `verify:` would run it twice per boundary for no gain. The rationale's wording is nonetheless what
  invited the misreading, so it now names the mechanism explicitly instead of assuming it — a
  clarification, not a concession on the substance.
