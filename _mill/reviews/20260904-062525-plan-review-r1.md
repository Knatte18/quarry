## Findings

### [NIT:consistency] t.TempDir() contradicts the repo's .scratch convention
**Demoted-from:** BLOCKING
**Location:** batch 1 card 4; batch 3 cards 14, 15; batch 4 card 18
**Issue:** Every filesystem fixture is prescribed as `t.TempDir()`, but `internal/engine/scratchtree_test.go`'s `writeScratchTree` doc states the opposite convention verbatim — "It never calls t.TempDir(): the system temp directory is banned by this task's constraints, and .scratch/ — gitignored at the repository root — is the sanctioned location instead" — and every engine test builds trees under `.scratch/engine-tests/<name>/`.
**Fix:** Give the existing `.scratch/` convention an explicit disposition in `## Shared Decisions` — either adopt it for `quarry/` and `internal/cli` fixtures, or state why the ban was T3-scoped and does not bind T5a.

### [BLOCKING:scope] Card 22 Context omits the files its assertions name
**Location:** batch 5 card 22
**Issue:** `Requirements:` decodes stdout into `quarry.DirAnswer` and asserts on `Dir`, `Package`, `Language`, `Files`, `Name`, `Symbols`, `ID`, `Kind`, `Start`, `SigEnd`, `End`, `Signature`, but `Context:` lists neither `quarry/quarry.go` (where the alias is declared) nor `internal/engine/answer.go` (where those Go field names live); the JSON golden in Context carries wire keys, not field names.
**Fix:** Add `quarry/quarry.go` and `internal/engine/answer.go` to card 22's `Context:`.

### [BLOCKING:scope] Exit 3 is asserted but no card says how to produce it
**Location:** batch 4 cards 16, 18
**Issue:** Card 18 requires "the exit-3 message begins `internal error: `" and a failure envelope "for each non-zero code", but card 16 reaches `exitInternal` only via `os.Getwd` failure, a non-`IsNotExist` stat error, a `TOC` I/O error, or a stdout write failure — and no card names a fixture that triggers any of them, nor does `Run` expose a seam to force one.
**Fix:** Name the exit-3 fixture in card 18 (e.g. a target path whose parent component is a regular file, yielding an `ENOTDIR` stat that is not `IsNotExist`, or a failing `io.Writer` for stdout).

### [BLOCKING:design] Single-dash tokens after the verb are routed to the target slot
**Location:** batch 3 card 10
**Issue:** Card 10 defines a flag as "a token beginning with `--`" and "every non-flag token after the verb is a target", so `quarry toc -x` sets `target = "-x"` and exits 1 with `target not found: -x`, contradicting `flag-semantics`' closed flag set and the exit-2 unknown-flag mapping; only `-h` is rescued, by the help pre-scan.
**Fix:** State in card 10 that a post-verb token beginning with `-` and not matching `-h` is `usageError("unknown flag: <token>")`, and add the case to card 13's table.

### [BLOCKING:design] Card 20 leaves internal/cli red until card 21 runs
**Location:** batch 5 cards 20, 21
**Issue:** Card 20 creates `after_test.go` comparing against `docs/research/output-formats/after/*.txt`, which card 21 creates afterwards; on the implementer's machine (which card 21 requires to have the pinned checkout) `go test ./internal/cli/...` fails at the card-20 boundary on a missing golden, and no card states that this red state is expected or bounded.
**Fix:** Either state the ordering expectation explicitly in card 20 (batch verify is green only after card 21), or have the test skip with a reason when the golden file is absent and `-update` is not set.

### [NIT:consistency] Cards cite discussion.md without listing it in Context
**Location:** batch 2 cards 7, 8; batch 4 card 18
**Issue:** All three say "per `discussion.md`'s … test list / Testing block" while `_mill/discussion.md` is absent from their `Context:`; batch 3 card 9 does list it, so the plan is inconsistent with itself about whether that file is readable.
**Fix:** Add `_mill/discussion.md` to those three cards' `Context:`, or drop the citation since each card already enumerates the list inline.

### [NIT:scope] Card 23 asserts before-side facts without the before-side file
**Location:** batch 5 card 23
**Issue:** The card requires `after/INDEX.md` to record that the before side "reads `dirs`, `files`, `ok`", "puts `generated` before `header`", repeats the directory prefix on every path, and used the `quarry toc dir|file <target>` split — all facts of `docs/research/output-formats/toc-dir.txt`, which is not in `Context:` (only the before-side `INDEX.md` is).
**Fix:** Add `docs/research/output-formats/toc-dir.txt` and `toc-file.txt` to card 23's `Context:`.
