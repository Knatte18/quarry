## Findings

### [NIT:consistency] `resolve_state_dir`'s `env` arg missing from its callers
**Demoted-from:** BLOCKING
**Location:** batch 3 / card 9 (and card 21's call sites)
**Issue:** The card lists `resolve_state_dir(target_dir, cache_dir)` and then requires it to take an explicit `env` mapping and raise `GateError` unless both `QUARRY_STATE_DIR` and `QUARRY_BUILD_TAGS` are scrubbed — but the four declared callers `gate_cold_before(target_dir, cache_dir)`, `gate_cold_after(events, target_dir, cache_dir)`, `daemon_pid(target_dir, cache_dir, lang)`, and `wait_for_daemon_exit(target_dir, cache_dir, timeout_s, lang)` carry no `env`, so they cannot satisfy it; only `run_gates(..., env)` and card 17's `warm_daemon(..., env, cache_dir)` thread it.
**Fix:** State one signature set — add `env` to the four cold/daemon helpers and to card 21's calls to `gate_cold_before` and `wait_for_daemon_exit`.

### [BLOCKING:design] `gate_cold_before` keys on a file card 9 declares unreliable
**Location:** batch 3 / card 9; batch 6 / card 21
**Issue:** `gate_cold_before` is fatal on the mere existence of `daemon.json`, while `wait_for_daemon_exit`'s own rationale in the same card establishes that neither `daemon.json` nor the state directory is removed on daemon exit (verified: `ensureSupervised` only removes `daemon.sock`, in the next spawn's stale-socket cleanup). Card 21 rebuilds a failed cold attempt at the *same* `cold_worktree_template` path, hence the same `workspaceKey` and same state dir — so any attempt that started a supervised daemon then failed a different fatal gate makes attempts 2 and 3 fail `gate_cold_before` deterministically, and that outcome is not one of card 21's four dispositions. A resume of an interrupted repetition has the same shape.
**Fix:** Define coldness as pid-liveness (or staleness, as `daemonStale` does) rather than file presence, or require the cold driver to clear the resolved state directory before each attempt.

### [BLOCKING:scope] Probe transcript has no declared path and is not gitignored
**Location:** batch 6 / card 18; batch 8 / card 24
**Issue:** Card 18 records "the probe's own transcript path" in `probe.json` but no card says where that transcript lands; the `.gitignore` pattern card 1 adds covers only `results/**/raw/`, so any probe transcript written at the results root is tracked and undeclared, leaving card 24's commit either dirty or committing a file absent from `Creates:` and from `## All Files Touched`.
**Fix:** Name the probe transcript path explicitly in card 18 and place it under `results/<date>/raw/`, or add it to card 24's `Creates:` and the overview's file list.

### [NIT:consistency] `cold_cell.json` attributed to the wrong card
**Location:** batch 8 / cards 26, 27
**Issue:** Card 26's `--stage cold` is what writes `results/2026-08-29/cold_cell.json`, yet card 26 declares `Creates: none` and card 27 — which only runs `summarize.py` — declares it under `Creates:`.
**Fix:** Declare the file under card 26 and state in card 27 that it is committed there without being re-created.

### [NIT:consistency] Batch 1 scope contradicts card 4's derivation source
**Location:** batch 1 / Batch Scope vs card 4
**Issue:** The batch-local decision says the seven names are "declared exactly once, as the module-level constant `QUARRY_TOOLS`" and every deny-list is `QUARRY_TOOLS - allowed`, but card 2 also declares `quarry_tools:` in `ladder.yaml` and card 4's drift guard proves derivation from the *loaded* `Ladder.quarry_tools`.
**Fix:** Reword the scope to say `QUARRY_TOOLS` is the canonical-seven validation constant while `deny_list_for` derives from the loaded ladder's list.

### [NIT:design] `compare_warm_cold` cannot read the disposition it is specified against
**Location:** batch 5 / card 14
**Issue:** The requirement says it "emits no comparison when the cold cell's recorded disposition is `not-run` or `partial`", but the declared signature `compare_warm_cold(ladder, cells)` carries no disposition input; the behaviour is only reachable via the incomplete-cell rule.
**Fix:** Either state that both dispositions are covered by the incomplete-cell refusal, or add the disposition (or `results_root`) to the signature.

### [NIT:scope] Absent `cold_cell.json` / `probe.json` behaviour unspecified
**Location:** batch 5 / card 15
**Issue:** `build_summary`'s `_meta` reads the cold disposition from `cold_cell.json` and `denied_tools_advertised` from `probe.json`, but neither the requirement nor the tests say what happens when either file is missing — the exact state after a `--stage main`-only run.
**Fix:** Name the missing-file disposition (raise, or a null/`unknown` metadata value) and add a test for it.
