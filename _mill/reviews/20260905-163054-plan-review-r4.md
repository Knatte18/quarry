## Findings

### [BLOCKING:design] UTF-8 check dropped on the revision-side clause vote
**Location:** batch 2 card 6 / batch 6 card 34 (with card 8)
**Issue:** Card 6 requires `PackageClause` to *not* check UTF-8 validity and names `ClauseMapForFiles` as the caller that does; card 8 duly checks it, but card 34's revision-side path reads blobs through the git layer and calls `PackageClause` directly with no validity step anywhere, so an invalid-UTF-8 tracked `.go` file records a clause on the revision side and is skipped on the working-tree side. Verified against `dirPackage` in `internal/engine/walk.go`, which gates on `err != nil || !utf8.Valid(src)` before recording a clause, and against discussion.md's own contract for `PackageClause` ("`ok` is false for an unknown extension, unreadable UTF-8, a parse failure, or an empty clause"), which the plan departs from without recording a Shared Decision as its own departure rule requires.
**Fix:** Either restore the UTF-8 condition inside `PackageClause` (matching the discussion), or state the validity check explicitly in card 34's revision-side step, so both sides of a directory's vote apply one validity rule.

### [BLOCKING:design] Rewired dirPackage would read every file before the extension check
**Location:** batch 2 card 6
**Issue:** Card 6 removes the language and strategy lookups from `dirPackage` and tells it to keep "its own `os.ReadFile` and UTF-8 validity check where they are". In `internal/engine/walk.go` today those lookups run *before* the read (`LanguageForExtension` then `StrategyFor` then `os.ReadFile`), and `PackageClause(base, src)` needs the bytes in hand, so a literal reading makes pass one read every entry in every directory — binaries, testdata, assets — before the extension is consulted. The clauses map is unchanged, so the "behaviour-preserving" claim holds for output while the walk's own priced cost note in `walk.go` and the timing assertion in `internal/engine/loomyard_timing_test.go` (`TestResolve_TwentyGlyphsUnder150ms`, selected by this batch's `verify`) both regress.
**Fix:** State in card 6 that `dirPackage` keeps an extension guard ahead of `os.ReadFile` and calls `PackageClause` only for files whose extension resolves to a language.

### [NIT:decision] Card 37 leaves the stdout check's scope over internal/cli unstated
**Location:** batch 6 card 37
**Issue:** `internal/mcpserver/layering_test.go` derives both checks' scanned set from one helper, `checkedDirs`, shared by `TestFacadeOnly_NoDirectEngineImport` and `TestStdout_NoProductionWrite`. Card 37 widens the scanned set with `internal/cli` for the import check and says only that the stdout check "already enforces [this] for its own packages", giving no disposition for the widened directory — while explicitly forbidding the analogous widening for the engine import path.
**Fix:** Say in card 37 whether `TestStdout_NoProductionWrite` keeps its current two directories or gains `internal/cli`; the import check's widening must not silently carry the stdout rule onto a package this task did not decide about.

### [NIT:scope] Run-level exit-3 case for a failed git command is not planned
**Location:** batch 8 card 47
**Issue:** The discussion's CLI testing list names "a git invocation failing for another reason → exit 3 with the `internal error: ` prefix" as a `Run` table case; card 47's `TestRun_Delta` enumeration omits it, and `TestCodeForDeltaError` covers only the error-to-code mapping, not the message prefix `Run` actually emits.
**Fix:** Either add the case to card 47's enumeration or state in the card why it is unreachable from a fixture and that the mapping test stands in for it.
