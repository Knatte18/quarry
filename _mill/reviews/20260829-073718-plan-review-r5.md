## Findings

### [NIT:consistency] `go mod tidy` undoes card 6's own direct requirement
**Location:** batch 2 / card 6 **Issue:** the card adds `jsonschema-go` as a *direct* requirement, then prescribes `go mod tidy` in the same card, but nothing imports it until card 10 (whose `Edits:` is `none`), so tidy demotes it back to `// indirect` — exactly the state the second `go get` was justified as fixing. **Fix:** state the ordering explicitly, or move the `jsonschema-go` acquisition and the tidy into card 10 where the direct import first exists.

### [NIT:scope] Batch 1's edited engine test file is never compiled by any gate
**Location:** batch 1 / card 2 **Issue:** card 2 edits `internal/quarryengine/query/callers_test.go`, but the batch `verify:` is scoped to `./internal/cli/...` and the boundary gate `go build ./...` does not compile `_test.go` files, so nothing in the plan compiles that edit. **Fix:** name the gate that covers it (e.g. chain `go test ./internal/quarryengine/query/...` onto batch 1's verify).

### [NIT:consistency] Batch 2's external-interface list omits two consumed identifiers
**Location:** batch 2 / Batch Scope **Issue:** the enumeration names `inputSchemaFor`/`outputSchemaFor`/`unknownEntryKeys` but not `dropEntryProperty` (consumed by card 18) or the `docSentences` type (consumed by cards 21 and 22), both created in card 10. **Fix:** add both to the batch's stated external interface.

### [NIT:consistency] `ResolveLaunchTargetDir` spec is not expressible as written
**Location:** batch 2 / card 6 **Issue:** `filepath.Abs(os.Getwd())` is a two-value call in single-value position, and `os.Getwd()` already returns an absolute path, so the spec both fails to compile literally and describes a redundant call. **Fix:** restate as "`os.Getwd()`, returning its error wrapped".

### [NIT:consistency] toc_file's `result` wrapper diverges from the CLI without a stated rationale
**Location:** batch 5 / card 22 **Issue:** `tocFileOne` flattens `structToFields` output into the entry, while card 22 nests it under `Result`; batch 4 documents the identical divergence for `impact` as a batch-local decision, batch 5 does not. **Fix:** add the matching batch-local decision to batch 5's scope so the divergence is intentional on the record.

### [NIT:consistency] `.mcp.json` bare-map rationale is over-broad
**Location:** batch 7 / card 28 **Issue:** verified against installed marketplace plugins — `plugins/example-plugin/.mcp.json` is a bare server map while `external_plugins/context7/.mcp.json` uses `mcpServers`, both at a plugin root beside `.claude-plugin/plugin.json` — so "the bare-map form belongs at a plugin's own root" is not the discriminator; the prescribed repo-root `mcpServers` shape is nonetheless correct. **Fix:** trim the rationale to "project-scoped `.mcp.json` uses a top-level `mcpServers` object".
