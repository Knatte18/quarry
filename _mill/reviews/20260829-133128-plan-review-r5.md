## Findings

### [NIT:consistency] `run_gates` cannot derive its own deny-list
**Demoted-from:** BLOCKING
**Location:** batch 3 card 10 (vs. batch 1 card 4, batch 3 card 8)
**Issue:** `run_gates(events, config, run_model, repo_root, worktree, run_dir, cache_dir)` takes no `ladder`, but it must compose `gate_denied_tools_not_used(events, denied_names)` and card 4 defines the only deny-list source as `deny_list_for(ladder, config)`; `execute_run` (card 19) does hold `ladder` and passes it nowhere.
**Fix:** state the resolved signature — either add `ladder` to `run_gates` or have it take a precomputed `denied_names` argument — in card 10's `Requirements:`.

### [NIT:consistency] `denied_tool_attempts` is both dropped and kept
**Demoted-from:** BLOCKING
**Location:** batch 6 card 18 and batch 8 card 24 vs. batch 5 cards 13, 15
**Issue:** Cards 18 and 24 say that when the probe finds denied tools are hidden, the field "is dropped from the reported metrics"; card 13 explicitly keeps it in `METRICS` and card 15 reports it qualified by `denied_tool_attempts_reported`, arguing that dropping it would leave the flag qualifying nothing.
**Fix:** pick one disposition and state it in all four cards — most likely "always summarised, qualified by the probe flag" — and delete the "dropped" wording.

### [BLOCKING:design] `--stage` selector is specified only inside test bullets
**Location:** batch 6 card 22 (consumed by batch 8 cards 24, 25, 26)
**Issue:** The CLI `Requirements:` paragraph describes an unconditional probe→main→cold run and never says to add a `--stage` argument; the flag and its four values appear only in the test list, and its default value is never stated — yet cards 24/25/26 are each defined entirely by `--stage probe|main|cold`.
**Fix:** move `--stage {probe,main,cold,all}` and its default into card 22's CLI requirement, beside the order-of-operations sentence.

### [BLOCKING:design] No disposition for a partially-confirmed cold cell
**Location:** batch 6 card 21, batch 5 card 15, batch 8 cards 26, 27
**Issue:** Card 21 defines three dispositions that each assume uniformity across all three repetitions ("at least one", "every attempt failed", "all three"); a cell with e.g. one confirmed-cold run and two that exhausted `MAX_ATTEMPTS` on the native-fallback branch fits none, is `complete: false`, and card 15 excuses only a `not-run` cell — so card 27's mandatory zero exit is unreachable with no stated remedy.
**Fix:** state the disposition and the summariser's incomplete-list rule for a cold cell with 1..reps-1 confirmed repetitions.

### [BLOCKING:design] Turn-ceiling truncation has no gate or disposition
**Location:** batch 1 card 2 (`max_turns: 60`), batch 6 cards 19, 20
**Issue:** A run stopped by `--max-turns` leaves a `result` event with an error subtype and no fenced json block; card 19 classes that as "unparseable answer", card 20 invalidates and retries, and the third failure halts the entire 45-run paid matrix — so a config that legitimately needs more than 60 turns (plausibly a `none` control on task 01's ~60-file survey) is indistinguishable from a gate fault.
**Fix:** name the truncation case explicitly — the result event's `subtype`/`is_error` is already extracted — and state whether such a run is retried, recorded as a distinct outcome, or halts.

### [NIT:consistency] Main-matrix daemons are not drained before the cold cell
**Location:** batch 6 cards 20, 21
**Issue:** Card 21 waits `DAEMON_EXIT_TIMEOUT_S` between cold repetitions so "no cold run is timed alongside a resident daemon from its predecessor", but nothing drains the task-01/task-04 daemons the main matrix leaves resident when the cold cell opens — the same argument, one boundary earlier, on exactly the runs the warm-vs-cold contrast reads.
**Fix:** state whether the same wait applies before the first cold repetition, or why it is unnecessary there.

### [NIT:consistency] Drift guard asserts a ladder state `load_ladder` rejects
**Location:** batch 1 card 4 (vs. card 3)
**Issue:** The eighth-tool drift guard appends a fabricated tool to a loaded ladder's `quarry_tools`, but card 3 makes `load_ladder` raise on "a `quarry_tools` list that is not exactly the canonical seven", so the scenario the guard advertises ("with no per-config edit") is unreachable through the real file path.
**Fix:** say the guard mutates post-load and that adding a real eighth tool also requires relaxing the canonical-seven check.

### [NIT:scope] `internal/cli/paths.go` missing from card 17's `Context:`
**Location:** batch 6 card 17
**Issue:** `run_env()`'s requirement reasons about `workspaceKey` precedence and the `tags-<hex>` segment appended at every tier — both defined in `internal/cli/paths.go`, which is in card 9's `Context:` but not card 17's.
**Fix:** add `internal/cli/paths.go` to card 17's `Context:`, or cite `gates.resolve_state_dir` as the sole reference.
