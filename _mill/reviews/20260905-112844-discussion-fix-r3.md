## Fixed

- r3 — "[BLOCKING:design] Pack-freshness gate keys on quarry VCS state". Accurate and the most
  consequential finding in the whole review: `MergeProvenance` sets top-level `QuarryCommit`/
  `QuarryDirty` from `next`, not `existing` (`provenance.go:400–418`), so any commit between
  `ladder pack` and `run` — including the expected commit of the generated card and the tracked
  results root — would fail the gate and brick the root, while `quarry_dirty` is vacuously true on
  both sides once the pack writes a tracked file. D3 now states that the verification compares
  exactly one thing, `sha256(card pack block) == kickstart_pack.pack_sha256`; that
  `kickstart_pack.quarry_commit`/`quarry_dirty` are a record of pack-time state and never a
  comparand, with both structural reasons written out; that harness rule 1 is enforced by the
  per-invocation `invocations[]` record rather than by a gate; and the operator workflow between pack
  and run (pack, inspect, commit, then run), so committing in between is documented as expected. The
  testing section gains the anti-regression: a run whose `quarry_commit` differs from the pack's
  still proceeds.
- r3 — "[NIT:consistency] `ladder pack` flag set omits the claude binary". Accurate — D4 has `pack`
  call `CollectInvocation`, which executes the binary through `probeClaudeVersion`
  (`provenance.go:317–322`) and aborts on failure. D3 now declares `--claude-bin` with the same
  default `run` uses (`main.go:58`), and says why it is not optional dressing.
- r3 — "[NIT:consistency] Glyph substitution leaves e0/e2 cards stale". Accurate: `ladder pack`
  rewrites only the pack cell's sentinel block, so a substitution would leave e0 and e2 naming a
  symbol e1 no longer lists — an arm difference in the dimension under test. D7's substitution rule
  is now a six-step ordered procedure that includes hand-editing all three `Uses:` lists and
  re-deriving e2's `Files:` list, and states that the three lists being identical is enforced by eye
  because no code enforces it.
- r3 — "[NIT:consistency] `§8.2 of docs/rewrite-plan.md` does not exist". Accurate — the file has ten
  top-level sections and no subsections. The Problem section now cites §7 ("How Loomyard uses it")
  and quotes its "re-resolved, never cached" wording, then states why this bench deliberately does
  the opposite: the pin means a second resolve could only return the same answer while making the
  treatment non-identical across reps, and the re-resolution policy is not what is under test.
- r3 — "[NIT:scope] Sweep's grep misses the inline `len(Allowed)` spelling". Accurate: `gates.go:62`
  spells the same concept inline. D2's sweep table gains that row, marked semantically correct and
  unchanged, plus an explicit note that the sweep covers `len(Allowed)` spellings as well as
  `IsControl()` call sites, and that two texts are re-worded with no behaviour attached —
  `CheckGrantedToolUsed`'s doc comment and `config.go:239`'s validation message, both of which
  currently define "control" as "empty allowed list".
- r3 — "[NIT:decision] No pre-rep-1 existence check for the e0/e2 cards". Accepted rather than
  accepted-with-cost: `run`'s pre-rep-1 pass now stats every selected config's `card` file, so a
  typo'd path on `e2-files` fails before `e0` and `e1` spend API calls. One `os.Stat` per cell.
  Covered by a new testing bullet.
- r3 — "[NIT:consistency] One pack cell per letter vs one per file". Accurate — `pack_targets` is a
  single top-level list, so two pack cells have no defined meaning. D11's rule is now "at most one
  `pack: true` config in the whole file", with a note that a per-letter pack would need a per-letter
  target list first (a format change, not a validation relaxation). `config_test.go`'s bullet asserts
  rejection both within one letter and across two.
