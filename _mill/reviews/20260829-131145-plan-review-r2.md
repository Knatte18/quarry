## Findings

### [NIT:consistency] `gate_artifacts_present` can never pass where it runs
**Demoted-from:** BLOCKING
**Location:** batch 3 card 10 / batch 6 card 19
**Issue:** Card 10 makes `gate_artifacts_present(run_dir)` require `answer.redacted.json` and `score.json`, but card 19's pipeline order is "extract `usage.json`, run `run_gates`, invoke `score_run`, and only then `write_run_json`" — both files are written by `score_run`, which has not run yet, so every run fails a fatal gate and the whole matrix halts on attempt 3 of run 1.
**Fix:** Pin one order across both cards — either split `gate_artifacts_present` out of `run_gates` and call it after scoring, or move `score_run` ahead of `run_gates` and restate card 10's precondition.

### [BLOCKING:scope] `task_text_for` has no stated section boundary
**Location:** batch 6 card 19
**Issue:** `task_text_for` is specified only as "extract the task's `<TASK TEXT>` block", naming neither the heading (`## `<TASK TEXT>` (identical for A, B, C)`), the terminator, nor the `> ` blockquote stripping; over-reading past the section pulls in task 04's `## Notes for whoever scores this (ground truth — do not reveal to A/B/C)` (the three real callers and the decoy) and task 01's fasit leads, silently contaminating all 45 runs with the answer key.
**Fix:** Name the exact heading, the "stop at the next `## `" rule, the `> ` prefix strip, and a `HarnessError` when the section is absent — mirroring the specificity `schema_for` already carries.

### [BLOCKING:scope] cold-cell state-dir resolution ignores `QUARRY_BUILD_TAGS` and an unnamed cache dir
**Location:** batch 3 card 9 / batch 6 cards 17, 21
**Issue:** `internal/mcpserver/callcontext.go:76` calls `cli.ResolveBuildTags(buildTags)`, which falls back to `$QUARRY_BUILD_TAGS`, and `ResolveStateDir` then appends a `tags-<hex>` segment at every tier; `resolve_state_dir(target_dir, cache_dir)` models only `<cache_dir>/quarry/<workspace_key>`, and `run_env()` scrubs only `QUARRY_STATE_DIR` — so an operator with that variable set makes every `gate_cold_after` read an empty directory and declare a fatal native fallback. No card says where the production `cache_dir` argument comes from (`os.UserCacheDir` semantics: `$XDG_CACHE_HOME`, else `~/.cache`) either.
**Fix:** Have `run_env()` also remove `QUARRY_BUILD_TAGS` (and state the `QUARRY_CONFIG` disposition), and name the `cache_dir` derivation explicitly in the card that supplies it to `gate_cold_before`/`gate_cold_after`.

### [NIT:consistency] batch 6's tests require injection seams the implementation cards never declare
**Demoted-from:** BLOCKING
**Location:** batch 6 cards 16, 19, 20 vs card 22
**Issue:** Card 22 asserts `ensure_task_worktrees` "against an injected git runner" and attempt accounting "against an injected executor", but card 16's signatures (`build_worktree(ladder, path, sha)`, `ensure_task_worktrees(ladder)`) and card 20's `run_matrix(...)` declare no such parameter, and card 19's `execute_run` signature has none; card 12's `score_run(..., runner=...)` shows the plan knows the pattern.
**Fix:** Add the explicit `runner=`/`executor=` seam parameters to cards 16, 19, and 20's stated signatures, and spell out `run_matrix`'s full parameter list rather than `(...)`.

### [NIT:consistency] `worktree_dirtied` is observed after the restore that erases it
**Demoted-from:** BLOCKING
**Location:** batch 6 card 20
**Issue:** Card 20 says "call `restore_worktree` unconditionally and record the `worktree_dirtied` observation for that run", in that order; `restore_worktree` is `git reset --hard` + `clean -fdx`, so any observation taken after it is always `False`, and card 15's `worktree_dirtied_count` aggregate becomes a column of zeros.
**Fix:** State that `observe_worktree_dirtied` is taken inside `execute_run`/`run_gates` before `restore_worktree`, and that card 20 only carries the already-recorded value.

### [NIT:decision] `--max-turns` is named as depended-upon but never dispositioned
**Demoted-from:** BLOCKING
**Location:** overview `### Decision: every client flag the harness depends on was checked` / batch 6 cards 18, 19
**Issue:** The decision lists `--max-turns` among the flags all 46 dispatches depend on, but no card passes it — `build_argv` enumerates nine flags and omits it — so 45 paid runs and the probe launch with no turn bound, and the plan states no alternative cost ceiling.
**Fix:** Either give `build_argv` a `--max-turns` value sourced from `ladder.yaml` (identical across all 45 runs so it cannot bias a comparison), or drop the flag from the decision and say plainly that runs are unbounded.

### [BLOCKING:scope] card 17 names `EnsureServer` without listing its file
**Location:** batch 6 card 17
**Issue:** The `WARM_UP_TOOL` requirement rests on "`toc_file` and `toc_dir` reach the tree-sitter path directly and never `EnsureServer`", but card 17's `Context:` is `ladder_config.py`, `docs/mcp-setup.md`, `cmd/quarry-mcp/main.go`, `.mcp.json` — neither `internal/quarryengine/daemon/ensureserver.go` nor `internal/mcpserver/tools_toc.go` is listed, so the implementer cannot check the load-bearing claim without cold-start exploration.
**Fix:** Add both files to card 17's `Context:`, as cards 9 and 21 already do.

### [NIT:consistency] `B_PREAMBLE_BODY` as specified still contains `<TASK TEXT>`
**Location:** batch 1 card 5
**Issue:** `B_PREAMBLE_BODY` is defined as "the committed Agent B preamble's own body between those two blocks, copied verbatim", and the committed body between them (README lines 175–179) includes the literal `<TASK TEXT>` placeholder; `preamble_for` then appends the task text separately, so a literal reading emits both the placeholder and the text.
**Fix:** State that `B_PREAMBLE_BODY` ends at the `<TARGET_DIR>` paragraph and excludes the `<TASK TEXT>` line.
