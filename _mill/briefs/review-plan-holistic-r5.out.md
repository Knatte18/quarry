## Findings

### [BLOCKING:design] Card 16's -update run destroys the no-regression proof
**Location:** batch 4 / card 16
**Issue:** `compareAfterGolden` writes *every* row's file under `*updateGoldens` (after_test.go:103-111), so `go test -run TestAfter -update` rewrites `toc-dir.txt`, `toc-file.txt`, `toc-dir-text.txt`, `toc-file-text.txt` too; the card's follow-up claim that the four already-committed files "must compare equal **without having been regenerated**" is then false, and the re-run compares regenerated bytes against themselves.
**Impact:** this equality is named in batch 1's Batch Tests as the task's proof that card 3's shared encoder and card 4's symbol-line change altered nothing — as ordered, that proof cannot fire, and a real byte change to the four toc goldens would land silently (they are not in `Creates:` nor in `## All Files Touched`).
**Fix:** require the no-`-update` run *first* (each row is its own `t.Run`, so the four toc rows pass while the eight new rows fail on a missing golden), or require a `git diff --exit-code` over the four toc goldens after the update run.

### [BLOCKING:scope] Cards 11 and 12 assert on answer.go's key set without listing it
**Location:** batch 3 / cards 11 and 12
**Issue:** both cards' `Requirements:` pin JSON payload keys — "carries no unit key", "a payload whose status is found and which carries a directory answer", "found, a head and no members key" — but `ResolveResult` and `ExpandAnswer` and their `json:"...,omitempty"` tags are declared in `internal/engine/answer.go`, which neither card lists in `Context:` or `Edits:`. Card 12 lists `internal/engine/expand.go`, which declares only `NotATypeError` and the methods, not the answer struct.
**Fix:** add `internal/engine/answer.go` to both cards' `Context:`, as cards 3, 5, 10 and 14 already do.

### [BLOCKING:consistency] RenderResolveText branch 1 breaks the no-trailing-whitespace rule
**Location:** batch 1 / card 5
**Issue:** branch 1 (`r.Status == ""`) is specified as `<target> error[ <reason>]: <normalised error>`; with an empty `Error` field that renders `<target> error: ` — a trailing space, violating the invariant batch 1's scope states for every input and the card asserts with `assertNoTrailingWhitespaceAndOneNewline`. The card enumerates exactly three totality guards for externally-constructed values and omits this fourth one, though it is the same class of input.
**Fix:** state branch 1's behaviour for an empty `Error` (and for an empty `Unit` in branch 2's not-found clause), and add the row to card 5's table.
